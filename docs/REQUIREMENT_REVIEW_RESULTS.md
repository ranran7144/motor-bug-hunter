# Jevによる要件品質レビューの実測結果

2026-09-23にclassifier.devの`jev-1.13.0`で、8観点をそれぞれ二択として判定した。これは要件文の品質を見直すための実験結果であり、仕様の正しさや安全性の証明、判定精度の測定ではない。表示するconfidenceはAPIが返した値で、正解率ではない。

「異常」「速やかに」「停止」の判定境界がない。一方、「装置」という主体、「異常が発生した場合」というトリガ、「停止する」という結果は文中に存在するため、それらの**有無**と**精度**を分けて読めている。結果の原本は[サンプル判定JSON](jev-review/20260923-sample.json)と[判定表](jev-review/20260923-sample.md)に保存した。

## 仕様書の51要件

[小型モータ制御ECU要件仕様書](MOTOR_ECU_REQUIREMENTS.md)の`MEC-`行51件を、用語・数値・適用範囲などの文脈付きで判定した。51件すべてで8観点の回答があり、APIエラーは0件だった。1回の通信エラーを再試行して回復したため、APIリクエストは計49回となった。

| 観点 | 判定数 |
|---|---|
| 曖昧性 | `ambiguous` 1 / `clear` 50 |
| 検証可能性 | `not_testable` 1 / `testable` 50 |
| 単一要件性 | `compound` 11 / `atomic` 40 |
| 主体 | `missing` 50 / `specified` 1 |
| トリガ条件 | `missing` 0 / `specified` 51 |
| 完了条件 | `missing` 0 / `specified` 51 |
| 定量条件 | `insufficient` 0 / `sufficient` 51 |
| 安全関連 | `safety_related` 35 / `ordinary` 16 |

品質7観点のいずれかで指摘された「要レビュー」は50件だった。この数値は、特に主体の`missing`判定に強く左右される。仕様書の適用範囲には制御ソフトウェアの説明があるが、多くの要件行は「〜すること」という主体省略形で書かれている。Jevは文脈付きでも50件を`missing`と判定した。各要件を担当する制御ソフトウェア・評価ハーネス等を明記するか、責務の割当てを仕様内で明確にしてから、人が再判定するのが次の作業となる。これを確定した欠陥50件とは扱わない。

`MEC-NFR-002`は曖昧かつ検証不可と判定された。複合要件の指摘には、初期値を列挙する`MEC-INI-001`、ラッチ中のPWMと始動禁止をまとめた`MEC-LAT-001`などが含まれる。分割すべきかは、個別に検証単位を確認する。

結果の原本は[全件判定JSON](jev-review/20260923-spec.json)と[判定表](jev-review/20260923-spec.md)に保存した。同じフォルダに、入力、質問定義、ソースの写し、ハッシュと実行設定も保存している。8観点の確率は相互に独立と仮定せず、積算していない。安全関連は分類であり、品質上の欠陥数に含めていない。
